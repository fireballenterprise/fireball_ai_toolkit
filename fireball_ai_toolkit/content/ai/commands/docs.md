Gather what changed on this branch:

!`uv run --no-sync python -m modules.toolkit.repo.route "pr_diff"`

If that fails (e.g. no base branch found), fall back to `git status` and `git diff` against HEAD to
see uncommitted changes instead.

Using that diff, audit every doc and AI-config file that could be stale because of it. At minimum
check:

1. **Root `README.md`** — Setup, Project Structure, Invoke Tasks, AI Prompts, Modules sections.
2. **Module READMEs** (`modules/*/README.md`) — for every module touched by the diff.
3. **`.fireball_ai_toolkit/toolkit/instructions/*.md` + `.fireball_ai_toolkit/<repo>/instructions/*.md`** — the source of truth for all
   AI rules; look for now-stale references to removed/renamed modules, commands, tasks, or config
   keys. (Edit `.fireball_ai_toolkit/toolkit/` via `fireball_ai_toolkit`'s `content/`, not in place.)
4. **`AGENTS.md` / `CLAUDE.md`** — generated pointer files; regenerated by `apply`, never
   hand-edited.
5. **Generated AI-provider files** — `.github/prompts/`, `.github/instructions/`, `.claude/`,
   `.clinerules/workflows/`, `.sidecar/`, `AGENTS.md`, `CLAUDE.md`. Never hand-edit these; if the
   change affects shared tooling, edit `fireball_ai_toolkit`'s `content/` (or this repo's
   `.fireball_ai_toolkit/<repo>/`) and re-run `invoke ai_toolkit.apply`.
6. **Any example/config file describing setup** — if `setup.sh`, `setup.ps1`, or the setup module
   changed what gets generated.
7. Any other `*.md` file that references a file, command, module, or behavior touched by the diff.

For each stale doc you find, fix it directly — this is a repo-local consistency sweep, not a
cross-repo sync, so no confirmation is needed before editing; git history is the safety net.

When done, report a short summary: which files you updated and why, or "no doc drift found" if
everything was already current.
